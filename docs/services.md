# Услуги и ценообразование (Service Engine 2.0)

Архитектура каталога услуг, моделей ценообразования, валидации параметров заказа и интеграции с исполнителем Lua.

## Модели ценообразования (`price_type`)

Каждая услуга в таблице `services` объявляет тип расчёта стоимости (`price_type`) и конфигурацию (`pricing_config`):

| Тип (`PriceType`) | Описание | Параметры клиента | Что валидирует сервер |
|---|---|---|---|
| `fixed` | Фиксированная стоимость | Не требуются | Использует базовую цену `service.price` и длительность `service.duration`. |
| `custom` | Произвольная сумма (Steam-пополнения, донаты) | `custom_amount: Decimal`, опционально `form: dict` | `min <= custom_amount <= max`, кратность `step`, валидация полей `form`. |
| `tiered` | Тарифные планы и ступени (например, дни подписки, слоты) | `tier_code: str` | Существование `tier_code` в `pricing_config.tiers`, цена и длительность берутся из выбранного тарифа. |
| `configurable` | Конфигуратор ресурсов (слайдеры, переключатели, мультипликаторы) | `components: dict[str, Any]` | Значения компонентов в диапазонах `min`..`max`, расчёт формулы: базовая цена + сумма компонентных цен. |

## Авторитетный серверный расчёт (Zero Trust to Client)

Расчёт стоимости заказа **никогда не доверяется клиенту**:
* В схеме `PaymentCreate` прямое поле `amount` для `target=service` **запрещено** (вызывает ошибку валидации).
* Перед созданием заказа или счёта на оплату вызывается авторитарный серверный метод:
  `src/services/pricing.py::resolve_service_order(service, custom_amount=..., tier_code=..., components=..., form=...)`
* Метод возвращает `ResolvedOrder`:
  - `price`: итоговая цена (с учётом компонентов, тарифов или произвольной суммы).
  - `duration`: срок действия услуги в днях (или `None` для бессрочных/одноразовых).
  - `effective_settings`: результирующие настройки услуги (глубокое слияние базовых настроек услуги и настроек выбранных компонентов/тарифов).
  - `order_config`: снимок конфигурации заказа для истории.

## Применение промокодов

Скидки применяются сервером строго к авторитетной цене `resolved.price`:
- Процентная скидка или фиксированная сумма.
- Если скидка составляет 100%, создание платежа отклоняется с указанием оформить бесплатную выдачу через `POST /api/v1/user/services/create`.

## Передача параметров заказа в Lua (`ctx.order`)

При доставке и исполнении жизненного цикла услуги (`create`, `renew`, `freeze`, `unfreeze`, `delete`) исполнитель LuaWorker получает полный контекст заказа:
```lua
ctx.order = {
    id = 123,
    service_id = "uuid-...",
    price_type = "configurable",     -- fixed | custom | tiered | configurable
    custom_amount = 500.0,
    tier_code = "pro_month",
    components = { vcpu = 4, ram_gb = 16 },
    form = { steam_login = "player1" },
    effective_settings = { ... }     -- финальный конфиг ресурсов после слияния
}
```

Скрипт Lua может безопасно использовать поля `ctx.order.form` и `ctx.order.components` для автоматического провижининга во внешних API (Pterodactyl, Proxmox, панели хостинга, игровые боты).
